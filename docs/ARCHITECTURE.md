### Layer Responsibilities

| Layer | Storage | Purpose | Update Pattern |
|-------|---------|---------|----------------|
| **Landing** | UC Volume `/Volumes/credit_card_dev/raw/landing/` | Raw source files in native format | Write-once from data generator |
| **Bronze** | `credit_card_dev.bronze` (13 tables + dq + logs) | Immutable log; preserves raw data with metadata | Append-only (Auto Loader / batch MERGE) |

| **Gold** | `credit_card_dev.gold` (4 dims + 3 facts) | Business-ready star schema with SCD2 | SCD2 MERGE (dims), full/append (facts) |
| **Control** | `credit_card_dev.control` | Watermarks for incremental loads | MERGE upsert |

## 4. Silver Layer (Cleansing & Validation)

### Silver Tables (8 total)

| Table | Source (Bronze) | Key Transforms | Dedup Key |
|-------|----------------|---------------|-----------|
| `customer_clean` | `crm_customer_master` + `crm_customer_address` | row_number dedup, gender→M/F/U, credit_score 300-850, email regex, age from DOB | `customer_id` |
| `card_clean` | `card_details` + `card_status` | latest status join, limit≥0, card_type/network standardization | `card_id` |
| `transaction_clean` | `txn_transactions` | amount>0 filter, date+time→datetime, MCC enrichment, customer_id via card | `transaction_id` |
| `statement_clean` | `billing_statements` | balance validation, utilization_ratio, payment_due_flag | `statement_id` |
| `payment_clean` | `billing_payments` | payment_method standardization, linkage to statements | `payment_id` |
| `default_clean` | `collections_defaults` | lag DPD analysis, is_repeat_default, dormancy_period, dpd_trend | `default_id` |
| `recovery_clean` | `collections_recovery` | recovery_method/status standardization | `recovery_id` |
| `customer_360_view` | All silver tables | Full outer join + aggregation per customer; risk_band, total_spend, avg_txn | `customer_id` |

### DQ Framework (8 check types)

| Check | Function | Description |
|-------|----------|-------------|
| Null check | `check_nulls()` | Null % per column vs threshold (default 5%) |
| PK duplicate | `check_duplicates()` | Duplicate PK combinations |
| Full row dedup | `check_full_row_dedup()` | Exact full-row duplicates |
| FK validity | `check_fk_validity()` | Orphan FK detection |
| Range check | `check_range()` | Min/max value bounds |
| Domain check | `check_domain()` | Accepted values list |
| Regex check | `check_regex()` | Pattern validation |
| Reconciliation | `reconcile_counts()` | Source vs target row count |

Bad records → `dq_quarantine` table. DQ scores → `silver.dq_scores` (partitioned by `run_date`).

## 5. Gold Layer (Star Schema)

### Dimensions

#### `dim_date`
- **Source:** `bronze.dim_calendar`
- **Grain:** 1 row per day
- **SK:** `date_sk` (INT, YYYYMMDD format)
- **Key columns:** `full_date`, `day`, `month`, `year`, `quarter`, `day_of_week`, `is_weekend`, `is_holiday`, `fiscal_year`, `fiscal_quarter`
- **Build:** Full refresh (overwrite)

#### `dim_geography`
- **Source:** `bronze.ref_country` + `bronze.ref_state`
- **Grain:** 1 row per (country_code, state_code) combination
- **SK:** `geo_sk`
- **Key columns:** `country_code`, `country_name`, `state_code`, `state_name`, `state_region`, `country_region`, `currency_code`
- **Build:** Full refresh
- **Note:** Had to rename `ref_state.region` → `state_region` before join to avoid ambiguous column error

#### `dim_customer` (SCD Type 2)
- **Source:** `silver.customer_clean`
- **SK:** `customer_sk` (surrogate, per version)
- **NK:** `customer_id`
- **SCD2 tracked columns:** `credit_score`, `annual_income`, `employment_status`, `marital_status`, `city`, `state_code`, `country_code`
- **Change detection:** MD5 hash of tracked columns
- **SCD2 columns:** `effective_date`, `expiry_date`, `is_current`, `scd_hash`
- **FK:** `geo_sk` → `dim_geography`
- **Build:** SCD2 MERGE (delta table)

#### `dim_card` (SCD Type 2)
- **Source:** `silver.card_clean`
- **SK:** `card_sk` (surrogate, per version)
- **NK:** `card_id`
- **SCD2 tracked columns:** `credit_limit`, `cash_limit`, `interest_rate`, `current_status`
- **Change detection:** MD5 hash
- **SCD2 columns:** `effective_date`, `expiry_date`, `is_current`, `scd_hash`
- **FK:** `customer_sk` → `dim_customer` (resolved via `customer_id` lookup)

### Fact Tables

#### `fact_transaction`
- **Source:** `silver.transaction_clean`
- **Grain:** 1 row per transaction
- **SK:** `txn_sk`
- **FKs:** `customer_sk`, `card_sk`, `date_sk`, `geo_sk`
- **Measures:** `amount`
- **Degenerate dimensions:** `currency_code`, `merchant_name`, `merchant_category_code`, `merchant_category_desc`, `transaction_type`, `pos_entry_mode`
- **Build:** Full refresh with broadcast hash joins on all 4 dims
- **Note:** Serverless compute doesn't support `.cache()`, so removed caching pattern

#### `fact_statement`
- **Source:** `silver.statement_clean` + `silver.payment_clean`
- **Grain:** 1 row per statement
- **SK:** `statement_sk`
- **FKs:** `customer_sk`, `card_sk`, `statement_date_sk`, `due_date_sk`
- **Measures:** `opening_balance`, `total_purchases`, `total_payments`, `total_credits`, `interest_charged`, `fees_charged`, `closing_balance`, `minimum_due`, `utilization_ratio`, `payment_ratio`
- **Note:** `dim_card` stores `customer_sk` not `customer_id` — join on `customer_sk` directly

#### `fact_default_analysis`
- **Source:** `silver.default_clean` + `silver.recovery_clean`
- **Grain:** 1 row per default event with recovery info
- **SK:** `default_sk`
- **FKs:** `customer_sk`, `card_sk`, `default_date_sk`
- **Measures:** `days_past_due`, `outstanding_amount`, `recovery_amount`
- **Attributes:** `collection_stage`, `is_repeat_default`, `dormancy_period`, `dpd_trend`, `recovery_method`, `recovery_status`

### Gold DAG Order

```
gold_dim_date ──────────────────────┐
gold_dim_geography → gold_dim_customer → gold_dim_card ──┬─────────────────────┐
                                     │                    │                     │
                                     │  gold_fact_transaction                  │
                                     │  gold_fact_statement                     │
                                     │  gold_fact_default                       │
                                     └─────────────────────────────────────────┘
                                                                               │
                                                                         gold_validate
```

### Star Schema Relationships

```
dim_customer ──┬── fact_transaction     (customer_sk)
               ├── fact_statement        (customer_sk)
               └── fact_default_analysis (customer_sk)

dim_card ──┬── fact_transaction     (card_sk)
           ├── fact_statement        (card_sk)
           └── fact_default_analysis (card_sk)

dim_date ──┬── fact_transaction     (date_sk)
           ├── fact_statement        (statement_date_sk)
           ├── fact_statement        (due_date_sk)
           └── fact_default_analysis (default_date_sk)

dim_geography ─── fact_transaction     (geo_sk)
```

| Check | Details |
|-------|---------|

| **FK integrity** | 11 FK relationships checked (0 orphans = pass) |

| **Sentinel check** | Orphan fact rows with FK = -1 |

## 9. Key Decisions & Learnings

| Decision | Context | Resolution |
|----------|---------|-----------|
| Serverless compute | No `.cache()` support | Removed caching; broadcast join hints |
| dim_geography region | Both `ref_country.region` and `ref_state.region` | Renamed `state.region` → `state_region` before join |
| dim_card → dim_customer FK | `dim_card` stores `customer_sk` not `customer_id` | Join on `customer_sk` directly in fact notebook |
| SCD2 expiry column naming | Both `dim_customer` and `dim_card` use `expiry_date` | Standardized via migration + code update |
| dim_date join | Serverless rejects STRING→INT type mismatch | Join on `date_sk` (INT, yyyyMMdd format) |
